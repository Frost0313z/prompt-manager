# 📝 프롬프트 매니저 (Prompt Manager)

![Python](https://img.shields.io/badge/python-3.10%2B-blue?logo=python&logoColor=white)
![No dependencies](https://img.shields.io/badge/dependencies-none-brightgreen)
![License: MIT](https://img.shields.io/badge/license-MIT-lightgrey)

터미널에서 메뉴를 선택해 나만의 AI 프롬프트를 등록하고 관리하는 콘솔 프로그램입니다.
텍스트/이미지/영상 생성용 프롬프트, 페르소나 설계안처럼 흩어지기 쉬운 프롬프트를 카테고리와 즐겨찾기로 정리합니다.

Codyssey 대전 캠퍼스 "Python & Git 기초" 미션 결과물이며, 외부 라이브러리 없이 표준 문법만으로 구현했습니다.

## 🚀 빠른 시작

```bash
git clone https://github.com/Frost0313z/prompt-manager.git
cd prompt-manager
python main.py
```

- Python 3.10 이상 필요
- 설치할 외부 라이브러리 없음 (표준 라이브러리만 사용)
- 실행 중 추가한 프롬프트와 즐겨찾기 상태는 그 실행 동안만 유지되고, 종료하면 초기화됩니다
- 시작 시 예시 프롬프트 3개가 기본 데이터로 미리 등록되어 있습니다

## 📋 기능

| 번호 | 기능 | 설명 |
|:---:|---|---|
| 1 | ➕ 프롬프트 추가 | 제목/내용/카테고리를 입력해 새 프롬프트를 등록합니다. |
| 2 | 📃 프롬프트 목록 | 등록된 모든 프롬프트를 번호와 함께 출력합니다. |
| 3 | 🗂️ 카테고리별 조회 | 카테고리를 선택해 해당 프롬프트만 조회합니다. |
| 4 | 🔍 프롬프트 검색 | 제목/내용에 포함된 키워드로 검색합니다. |
| 5 | 📖 프롬프트 상세 보기 | 번호를 입력해 프롬프트 전체 내용을 확인합니다. |
| 6 | ⭐ 즐겨찾기 관리 | 번호를 입력해 즐겨찾기를 켜고 끕니다. |
| 7 | 🌟 즐겨찾기 목록 | 즐겨찾기한 프롬프트만 모아서 봅니다. |
| 0 | 🚪 종료 | 프로그램을 종료합니다. |

## 💻 실행 예시

**메인 메뉴**

```
=== 나만의 프롬프트 관리 ===
1. 프롬프트 추가
2. 프롬프트 목록
3. 카테고리별 조회
4. 프롬프트 검색
5. 프롬프트 상세 보기
6. 즐겨찾기 관리
7. 즐겨찾기 목록
0. 종료

선택: 2
```

**프롬프트 목록**

```
=== 프롬프트 목록 ===
1. [텍스트 생성] 블로그 서론 작성 도우미
2. [이미지 생성] 제품 상세페이지 썸네일 생성
3. [페르소나] 시니어 백엔드 개발자 페르소나 ⭐

총 3개의 프롬프트
```

**프롬프트 상세 보기**

```
=== 프롬프트 상세 보기 ===
번호 입력: 1
──────────────────────────────
제목: 블로그 서론 작성 도우미
카테고리: 텍스트 생성
즐겨찾기: -
──────────────────────────────
내용:
당신은 10년 차 콘텐츠 마케터입니다. 아래 주제에 대해 독자의 호기심을 자극하는
블로그 서론을 3문단으로 작성해주세요. 마지막 문단은 본문을 계속 읽고 싶게
만드는 질문으로 마무리하세요.
──────────────────────────────
```

**즐겨찾기 추가 → 즐겨찾기 목록**

```
=== 즐겨찾기 관리 ===
프롬프트 번호 입력: 2
'제품 상세페이지 썸네일 생성' 프롬프트를 즐겨찾기에 추가했습니다!

=== 즐겨찾기 목록 ===
1. [이미지 생성] 제품 상세페이지 썸네일 생성 ⭐
2. [페르소나] 시니어 백엔드 개발자 페르소나 ⭐

총 2개의 즐겨찾기
```

## 🗂 카테고리

`텍스트 생성` · `이미지 생성` · `영상 생성` · `페르소나` · `자동화` · `기타`

프롬프트 추가 시 번호로 선택하거나, 목록에 없는 이름을 직접 입력해 새 카테고리를 쓸 수도 있습니다.

## 🧱 프로젝트 구조

```
prompt-manager/
├── main.py                 # 실행 진입점 (Windows 콘솔 UTF-8 설정 포함)
└── prompt_manager/
    ├── __init__.py
    ├── data.py              # 기본 프롬프트 데이터, 카테고리 목록
    └── core.py              # 메뉴 출력 및 기능별 함수 (add_prompt, show_list, ...)
```

함수는 기능 단위로 분리되어 있고, 메뉴 선택지는 `ACTIONS` 딕셔너리로 함수에 매핑됩니다.

## 🧠 설계 노트

**데이터 구조 — 리스트 안에 딕셔너리**
프롬프트를 `prompts: list[dict]`로 저장합니다. 리스트는 추가된 순서를 그대로 유지해 메뉴 번호(1, 2, 3 ...)와 자연스럽게 대응되고, 딕셔너리는 `title`/`content`/`category`/`favorite` 필드를 이름으로 접근할 수 있어 튜플보다 읽기 쉽습니다. `dataclass`나 클래스도 대안이었지만, 외부 라이브러리 없이 딕셔너리 하나로 표현 가능한 단순한 구조라 과하다고 판단했습니다. 단점은 필드명 오타를 정적으로 잡아주지 못한다는 것인데, 모든 딕셔너리를 `data.py`의 `DEFAULT_PROMPTS`와 `add_prompt`의 append 한 곳에서만 만들도록 제한해 리스크를 줄였습니다.

**메뉴 루프 — `while True` + 문자열 `"0"` 종료 조건**
`run()`은 `while True`로 무한 반복하며 매 반복마다 메뉴를 출력하고 입력을 받습니다. 콘솔 프로그램은 애초에 "언제 멈출지 정해져 있지 않은" 상태를 다루므로 `for`보다 `while True`가 자연스럽고, 종료 조건은 별도 플래그 변수 대신 `choice == "0": break`로 그 자리에서 바로 표현해 흐름을 한눈에 볼 수 있게 했습니다. `ACTIONS` 딕셔너리에 없는 입력은 `continue`로 다시 메뉴로 돌아가게 해 잘못된 입력이 프로그램을 죽이지 않도록 했습니다.

**브랜치 전략**
`프롬프트 목록 조회` 기능은 미션 요구사항(“main 이외의 브랜치에서 작업 후 병합”)에 따라 `feature/list` 브랜치를 따로 만들어 작업했습니다. 목록 조회는 다른 기능에 의존하지 않는 독립적인 조회 기능이라 브랜치를 분리해도 충돌 위험이 없었고, 이후 `merge --no-ff`로 병합해 “이 기능은 별도로 개발되었다”는 이력을 로그에 남겼습니다. 나머지 기능(검색, 상세 보기, 즐겨찾기 등)은 서로 같은 `core.py` 파일을 계속 확장하는 형태라 브랜치를 나누면 병합 충돌만 늘어난다고 판단해 `main`에서 순차적으로 커밋했습니다.

**데이터 영속화 제안 (보너스 미구현)**
현재는 실행 중에만 메모리(리스트)에 데이터가 유지되고 종료 시 초기화됩니다. 다음 확장 시에는 `json.dump`/`json.load`로 `prompts.json`에 저장하는 방식을 제안합니다. 리스트의 각 딕셔너리를 JSON 배열의 객체로 1:1 매핑할 수 있어 별도 변환 로직 없이 그대로 직렬화할 수 있고, 프로그램 시작 시 파일이 있으면 불러오고 없으면 `DEFAULT_PROMPTS`로 초기화하는 방식이면 기존 구조를 거의 바꾸지 않고 확장할 수 있습니다.

**동명 프롬프트 · 카테고리 충돌 처리 정책**
프롬프트는 제목이 아니라 리스트 안의 번호(인덱스)로 구분합니다. 따라서 같은 제목을 여러 번 등록해도 각각 별개 항목으로 취급되어 덮어쓰지 않고 모두 유지됩니다(의도적으로 중복 등록을 허용 — 같은 주제의 프롬프트를 버전별로 여러 개 남기는 사용 시나리오를 막지 않기 위함). 카테고리는 미리 정의된 6개 목록에서 고르거나 새 이름을 직접 입력할 수 있는데, 새 카테고리명이 기존 이름과 완전히 같은 문자열이면 같은 카테고리로 합쳐지고, 다르면 새 카테고리로 취급됩니다. 별도의 충돌 감지·병합 로직은 없으며, 대소문자나 띄어쓰기가 다르면 다른 카테고리로 분리된다는 점을 사용자가 유의해야 합니다.
